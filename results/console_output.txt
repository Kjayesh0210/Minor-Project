EXPERIMENT 3 - Outlier handling   [k=6, n=400, 8 instances]
==============================================================================
     z       plain      robust    delaunay   (mean radius over 8 instances)
  --------------------------------------------------------
     0      60.299      60.299      86.235
     2      54.372      44.971      68.515
     4      52.329      40.318      51.978
     6      51.687      36.718      42.888
     8      50.637      26.068      28.026
    10      50.100      23.243      25.007
    12      49.626      20.877      23.890
    14      49.215      20.020      23.141
    16      48.833      20.330      22.535
    18      48.519      17.905      22.070
    20      48.307      20.493      21.828

  Abandoning just 20 of 400 points (5.0%) cuts the radius by 20% - the price of the last few stragglers.
  At z=0 the filter looks WORSE (86.2 vs 60.3): it threw the
  strays away, so covering them again is expensive. It overtakes plain
  Gonzalez at z=4 and the dataset has 10 planted outliers - the
  crossover lands where the filter's own judgement says it should.

  Delaunay detector, two ways of scoring a point from the same mesh:
   threshold  min:prec  min:rec  min:F1   mean:F1
  ------------------------------------------------
         2.0      0.22     0.97    0.36      0.24
         3.0      0.34     0.96    0.50      0.28
         3.5      0.42     0.96    0.58      0.29
         5.0      0.67     0.93    0.77      0.35
         6.0      0.76     0.91    0.83      0.38
         8.0      0.91     0.89    0.89      0.45  <- best
        10.0      0.93     0.84    0.87      0.52
        12.0      0.95     0.84    0.88      0.57
        14.0      1.00     0.79    0.87      0.63

  min-edge scoring peaks at F1=0.89 (precision 0.91, recall 0.89);
  mean-edge scoring only reaches F1=0.63.
  Reason: a point on the RIM of a cluster has long edges reaching across
  the gap, so its mean is large and it is falsely flagged - but it still
  has a close neighbour inside the cluster, so its min stays small.
  The min IS the exact 1-NN distance, because the Delaunay graph
  contains the nearest-neighbour graph. No KD-tree, O(n) on the mesh.

  CAVEAT: the threshold 8.0 used above was picked from THIS sweep,
  on the same instances it is then scored on. That is optimistic. A
  defensible version picks the threshold on held-out instances; the
  README lists this as the first thing to fix.

  Head-to-head at n=250, z=8:
  method                             radius       ms   guarantee
  ------------------------------------------------------------------
  Charikar greedy                    24.552      3.2   3x, O(n^2 k log n)
  Robust Gonzalez                    26.574      0.1   none, O(nk)
  Delaunay filter + Gonzalez         30.963      1.9   none, O(n log n + nk)

EXPERIMENT 6 - Measured scaling vs stated complexity
==============================================================================
  algorithm                         fitted exponent            stated
  --------------------------------------------------------------------
  Gonzalez  O(nk)                              0.78            n^1.00
  Delaunay mesh  O(n log n)                    1.05       n^1.0 log n
  Delaunay MST seed  O(n log n)                1.02       n^1.0 log n
  dense MST seed  O(n^2)                       2.25            n^2.00
  Hochbaum-Shmoys  O(n^2 log n)                2.00       n^2.0 log n

  Log-log least-squares fit of measured runtime against n, using only
  n >= 400: below that, Python call overhead is larger than the work
  itself and every routine looks like O(1).
  The headline: dense MST seeding fits n^2 and the Delaunay MST seed fits
  n^1, which is the O(n^2) -> O(n log n) claim confirmed by measurement,
  not just asserted. A log n factor is invisible to a power-law fit, so
  an O(n log n) routine correctly reads as slightly above n^1.
